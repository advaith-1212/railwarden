# Configuration

Project config uses relative paths and resolves them dynamically. Validation
commands declare `cwd` and `argv`.

The V1 orchestration defaults are generated by `lfg init --yes`:

- `hermes.primary_model`, `hermes.fallback_model`, and
  `hermes.allow_fallback` describe the planning control plane.
- `providers.<name>.priority`, `providers.<name>.capabilities`, and
  `providers.<name>.cooldown_seconds` drive provider selection and recovery.
- `execution.require_plan_approval` keeps generated plans approval-gated.
- `execution.preserve_partial_work_on_handoff` keeps dirty worktrees and
  branches available for the next provider.
- `monitoring.git_graph` controls whether `lfg dashboard` includes the compact
  Git graph.

Work packages support `id`, `name`, `objective`, `dependencies`, `owned_paths`,
`forbidden_paths`, `acceptance_tests`, `preferred_providers`, `branch`,
`worktree`, and `status_notes`. Runtime truth lives in
`.lfg-runtime/state/tasks.json`; `status_notes` is only planner/user context.
